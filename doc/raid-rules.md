# Raid rules (`data/raid_rules.txt`)

Status: built and unit-tested (`src/raid_rules.*`, `tests/raid_rules_test.cpp`, `tests/party_planner_test.cpp`, one policy test). **Not run on a sim yet.** Off until `Module.forever-bots.RaidRulesFile` names the file.

A raid fight needs facts that the per-boss block of a dungeon file does not carry and that repeat across maps. They live in one text file, one row per line, `|` separated, `#` for comments.
The format is our own; no table or code of another project was copied.

| Row | Fields | Used by |
|---|---|---|
| `boss` | `map|entry|name` | the swap taunt (which unit is "the boss") |
| `add` | `map|entry|rank|name` | kill priority, rank 0 first; merged at start into each scenario's kill priority (the dungeon file's own ranks win), so the targeting and the planner's shared kill target both read it |
| `interrupt` | `map|spell_id|name` | the planner serves a cast with this spell id before any other cast (the nearest ready kickers go to it first) |
| `dispel` | `map|aura_id|magic/curse/disease/poison|name` | the planner gives a member that carries this aura to the nearest ready member of a class that can dispel the kind; `TurnRaidRules` sends the cast |
| `avoid` | `map|spell|spell_id|radius|name` | a ground effect (dynamic object, area trigger or, with core `Bot.Snapshot.GroundEffects.GameObjects`, a trap game object: kind 3, the trap's spell) of this spell is harmful with this radius (needs `AvoidGroundEffects = 1`) |
| `avoid` | `map|object|entry|radius|name` | parsed and kept; **not acted on**: a trap game object is listed by its trap spell (kind 3), so write it as an `avoid|spell` row with the trap spell (Jeklik's bomb GO 177764 is spell 19628, Liquid Fire GO 180125 is 23972) |
| `swap` | `map|boss_entry|aura_id|stacks|name` | the main tank holding `stacks` of this aura is handed over to another tank with fewer; the new main tank (a warrior) taunts the boss |
| `noaoe` | `map|boss_entry|name` (0 = whole map) | `Order::NoAoe` (`party_planner::NoAoeNow`); the fight rotation skips the area-damage rows while it is on |
| `leash` | `map|yards|name` | the route leader of a dungeon party pulls only hostiles within `yards` (10..80) of the route leg on this map; narrows `DungeonPullLeashYards`, never widens it; it also narrows the pick of a **new** target by a party already in a fight (the chase leash of 40 let the leader walk from the first pull on into the next pack), and the focus-fire pick of a member for units nobody fights yet; a target a bot already holds (its threat target, the walk after it) keeps the chase leash. Zul'Gurub: 15, so the leader does not pull the first (shelf) pack 20-30 yards off the ramp |
| `spread` | `map|boss_entry|yards|all/ranged/healers/melee|name` (boss_entry 0 = any engaged hostile) | while an engaged hostile of that entry is in view, the party plan keeps the members of the group at least `yards` apart (chain-style jumps, bombs); the planner settles the members one by one (immovable humans first, then by guid) and gives a member that is too close to a settled one the nearest clear point (`ground_avoid::EscapePoint`, at most 15 yards away); `TurnRaidSpacing` walks there. Tanks never move; a bot mid-cast does not move; one nudge per 5 s per bot; yards 2..60. Switch `RaidSpread` |
| `avoid_enemy` | `map|entry|yards|all/ranged/healers/melee|name` | a non-tank member of the group keeps at least `yards` from a live hostile of that entry (Holy Nova, melee reach, a charging add); same escape geometry as the telegraph escape, centered on the unit; a bot mid-cast holds unless that unit is casting. Switch `RaidAvoidEnemy` |
| `purge` | `map|aura_id|name` | an aura on an enemy that the plan has a priest (Dispel Magic 527) or shaman (Purge 370) remove: one job per party, the nearest ready purger and a backup that fires 700 ms later if the aura is still there. Switch `RaidPurge` |
| `mindcontrol` | `map|aura_id|name` | a member whose own aura list carries this aura is read as mind controlled: it is put on every plan member's do-not-attack list and the nearest ready mage polymorphs it (a backup after 700 ms, a recast every 6 s). Switch `RaidMindControl` |
| `pullpos` | `map|entry|x|y|z|yards|name` | the tank (the route leader) pulls a creature of this entry from this position (yards 2..40): out of combat it walks to within `yards` of it first (at most 30 s, then it pulls from where it is), once the pull has landed it goes back to it and holds there up to 15 s while the pack is on its way, and the other members wait for the tank to be in the fight (the tank-first hold has no exception for a member standing near the target). The row does not widen the pull leash: the tank still picks only what the leash lets it. Log line `pull_position:` (why `pull_position` or `pull_back`). Zul'Gurub: the shelf pack 11350/11371/11372 from route point 7 (-11872.5,-1287.7,82.3), before the stairs; the position is from the creature table, line of sight is not checked |
| `frontal` | `map|boss_entry|spell_id|name` | parsed and kept (`Table::IsFrontal`); the telegraph escape (a tank in a frontal cone steps out); no tank positioning yet, see the gaps |

Dispel spells by class (`DispelSpellFor`, first ranks; ids, dispel kinds and learn levels **verified 2026-11-12** against SpellName/SpellEffect/SpellLevels of the client data): priest Dispel Magic 527 and Cure Disease 528; paladin Cleanse 4987 (magic, level 42) and Purify 1152 (poison, disease); mage Remove Lesser Curse 475; druid Remove Curse 2782 and Cure Poison 8946; shaman Cure Poison 526 and Cure Disease 2870.
A healer on an emergency heal (a member below 20 %) is not given a dispel. A bot reads its **own** auras from its snapshot (`auras[]`, up to 16), so a member's debuff is seen when that member is one of the module's bots.

## Gaps (what the snapshot does not offer)

- **Game objects: solved by kind 3.** The core (branch `feature/ground-effect-traps`, `Bot.Snapshot.GroundEffects.GameObjects`, default 1) lists an armed trap game object (type trap, trap spell set, spawned, ready) within 30 yards as a `GroundEffect` of kind 3: `spell_id` is the GO's trap spell (Data3), `radius` is Data2/2 or the spell's own radius. No layout change. The module treats the kind like any other: only the spell id and the rows decide. Not covered: game objects that are not traps (no spell), and cores without the change (no kind 3 entries; the rows then match nothing). Known corrections: Jeklik's bomb radius is 5 (not 6); Liquid Fire is GO 180125 / trap 23972 (not 177764, which is the bomb).
- **Casts that land on an area** (Fireball, Deep Breath) arrive as `Telegraph` entries (layout 25: circle or cone, `spell_id`, `radius`, `cone_angle`). Since the telegraph escape (`TurnTelegraphEscape`, below) a bot inside one steps out; the `avoid|spell` rows act on ground effects and also mark a telegraph spell as lethal-class.
- **Debuffs on bots that are not the module's** (humans) are not in a snapshot; the core's party view (`PartyDebuff`, `dispel_type`) could feed the dispel plan once `PartyViewPlanner` adopts it.
- **No-AoE flag: consumed.** `noaoe` rows reach the party plan (`NoAoeNow`); the fight rotation (`bot_policy_turn_cast.cpp`) skips every row for which `rotation::IsAoeRow` is true while it is on. A row is area damage when its file line carries the keyword `aoe` (`row 999 aoe always self`) or its spell is in the built-in set (Cleave, Thunder Clap, Swipe, Multi-Shot, Blizzard, Flamestrike, Arcane Explosion, Cone of Cold, Frost Nova, Chain Lightning, Consecration, Fire Nova, Magma Totem, Shockwave, Blade Flurry; all ranks). `data/rotations.txt` is generated and not edited; the built-in set does the marking. Pet and totem abilities and out-of-rotation casts (Hunter Volley etc.) are not covered. Tested in `tests/rotation_data_test.cpp`.
- **Tank positioning for `frontal` rows: not built, and why.** The snapshot has what the geometry needs: the boss's `NearbyUnit::orientation`, the raid's positions (party view), the casts (`cast_spell_id`, `cast_remaining_ms`). What it does not have: (1) where a point is standable and reachable in the room (a `kProbePoint` answer exists per point, one probe per action, too slow to search a ring around the boss in the 1.5 s of the cast); (2) the room's bounds, so a point behind the boss can be inside a wall or off the ledge (Onyxia's cave, the Molten Core halls); (3) whether moving the tank drags the boss through the raid (a boss turns to its victim as it follows: the tank has to walk the long way round, which needs a path the module cannot plan). A pure-geometry step (stand on the far side of the boss from the raid centroid) is a few lines but untested against a real room, so it is left off. To build it: a per-boss `tank_spot` row (x, y, facing) in the raid rules (data, measured once on the sim) is the safe design; the tank walks to it at the pull and the raid stands elsewhere. `IsFrontal` and `IsFrontalAny` are used today only by the telegraph escape, for a tank that is in a frontal cone.
- **Swap needs a second tank.** With one tank nothing changes; the taunt is warrior only.

## Spacing, purge and mind control rows (spread, avoid_enemy, purge, mindcontrol)

Four row types added after the telegraph escape. Our own design: each is a plain data row plus a small step; nothing is taken from another project. All four are switched by `RaidSpread`, `RaidAvoidEnemy`, `RaidPurge`, `RaidMindControl` (default 1) and act only where the map has a row of their kind, so a run without rows is unchanged. Log events: `raid_spread:`, `raid_avoid_enemy:`, `raid_purge:`, `raid_mindcontrol:`.

Rows shipped (Zul'Gurub only), with their evidence: Venoxis (14507) casts Holy Nova 23858 (SpellRadius **15 yards, verified**), Renew 23895 on himself (periodic heal, **verified**: `classic_boss_venoxis.cpp`, creature_template_spell) and Holy Wrath 23979 on his victim. Rows: `avoid_enemy` 15 yards for `ranged` and for `healers` (Holy Nova); `spread` 10 yards for `ranged` and `healers` (Holy Wrath; **the 10-yard jump radius is an estimate**, the spell data we read does not give it); `purge` 23895; `mindcontrol` 24327 (Hakkar's Cause Insanity, aura type 6 = charm, **verified**). Onyxia has no row of these kinds (nothing verified).

Limits, stated plainly:
- **Positions only, no room geometry.** The nudge point is the nearest clear point by distance; the module cannot tell a wall or a ledge from open ground (same gap as the `frontal` tank spot). A nudge is capped at 15 yards from where the bot stands. A bot that has no clear point within the cap simply stays.
- **Humans cannot be moved**, only counted as taken positions (needs `PartyViewPlanner`); the plan moves the module's own bots.
- **Purge needs the aura to be seen.** The aura list of an enemy exists only as `target_auras` of a bot whose current target it is (layout 24, up to 8 auras); the module reads it from every member's snapshot, so the aura is found when any bot targets that enemy. The bots-side layout fields (`target_aura_count`, `target_auras[]`) exist in the SDK; whether the core fills them on the sim is **unverified**. Class spells: priest Dispel Magic 527 (level 18) and shaman Purge 370 (level 12), both effect 38 dispel type magic on a hostile target (SpellEffect), learn levels from `data/spell_costs.txt`. A hunter's Tranquilizing Shot 19801 is dispel type 9 (enrage) only, so it is not used; a mage has no Spellsteal in this client's spell data.
- **Mind control is read from the bot's own aura list**, so only a module bot that is controlled is recognized (a human member is not: the party view has no aura list). The controlled bot's own actions are whatever the core's charm AI does; the module does not stop them. Only a mage holds the member (Polymorph 118, works on a player in combat); a rogue's Sap needs a target out of combat and a priest's Shackle Undead holds undead only, so neither is used. The do-not-attack list is the targeting steps' existing avoid mechanism; a controlled player is a player-type unit, which the mob targeting does not pick anyway, so this is a belt and braces rule, area damage is not covered.

## Telegraph escape

`Module.forever-bots.TelegraphEscape` (default ON; it only acts on a map that has rules in the raid rule table, so dungeons and the open world are untouched) and `TelegraphEscapeCasters` (default 0). Needs the core's `Bot.Snapshot.Telegraphs = 1`. The step runs right after the ground-effect step: a bot that stands inside a telegraph (`party_view::TelegraphsHitting`) walks to `EscapeFrom(.., margin 3)`; the end point is kept for 3 s so it does not shift each tick; the log line is `telegraph_escape: bot= map= spell= to=`.
Who holds: a **tank** (role tank, or a warrior in a party with no role set) holds unless the spell is an `avoid|spell` row (lethal-class) or a `frontal` row of any boss of the map; a bot **mid-cast** (healer or caster) holds unless the spell is an `avoid|spell` row or `TelegraphEscapeCasters = 1`. Everyone else steps out of any telegraph. The tank exception for lethal rows is deliberate: Deep Breath kills a tank as well.

## Settings

    Module.forever-bots.RaidRulesFile = /srv/forever/sim/modules_runtime/forever-bots/data/raid_rules.txt
    Module.forever-bots.AvoidGroundEffects = 1       # for the avoid rows
    # core: Bot.Snapshot.GroundEffects = 1

A bad row is logged (`forever-bots: RaidRulesFile: line N: ...`) and skipped. The start log says `raid rules: N map(s) from <file>`.

## What a sim run checks

Onyxia (`Scenario = onyxia`, the 40-roster) and Zul'Gurub (`Scenario = id:3` with the 20-roster, `ScenarioRaid.id = 1`): the same run with and without `RaidRulesFile`. Compare bosses killed, deaths per raid, time per boss, and the log events `raid_dispel:`, `raid_swap_taunt:` and `interrupt_target:`. Expect `raid_dispel` for Curse of Blood and Shadow Word: Pain in Zul'Gurub; expect no `raid_swap_taunt` unless the roster has two tanks.
